# API

Детальное описание REST API трекера расходов. Полное интерактивное описание доступно в Swagger: **http://localhost:3001/api/docs**.

## Базовые соглашения

- **Базовый URL:** `http://localhost:3001` (порт из `PORT`, по умолчанию 3001).
- **Формат:** JSON (`application/json`).
- **Авторизация:** Bearer-токен JWT в заголовке `Authorization: Bearer <token>`. Защищены **все** эндпоинты, кроме `POST /auth/register` и `POST /auth/login` (помечены `@Public()`).
- **Идентификация:** после проверки JWT в `request.user` кладётся `{ id, email, name? }`; в контроллерах достаётся через `@CurrentUser()`.
- **Валидация:** глобальный `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`). Лишние поля отбрасываются/вызывают 400, query-параметры (`page`, `limit`, `month`, `year`) конвертируются в числа.
- **Ошибки:** формат NestJS — `{ statusCode, message, error? }`. `message` может быть строкой или массивом строк (class-validator).

### Коды ответов (типовые)

| Код           | Значение                  | Когда                                                                                 |
| ------------- | ------------------------- | ------------------------------------------------------------------------------------- |
| `400`         | Невалидное тело/параметры | Ошибки валидации DTO, `id` не UUID, `month`/`year` вне диапазона                      |
| `401`         | Требуется/невалиден токен | Без токена или подпись невалидна (`Требуется авторизация` / `Недействительный токен`) |
| `404`         | Не найдено или чужое      | Запись не найдена **или** принадлежит другому пользователю (намеренно неразличимы)    |
| `409`         | Конфликт                  | `POST /auth/register` — email уже занят                                               |
| `201` / `200` | Успех                     | Создание / чтение и мутации                                                           |

### Типы данных (соглашение)

- Денежные значения — `number` (в БД `Decimal(12,2)` приводится к числу).
- Даты — ISO-строки (в БД `DateTime` приводится `.toISOString()`).
- `passwordHash` никогда не отдаётся наружу.

## Auth — `/auth`

### `POST /auth/register` — публичный

Регистрация нового пользователя.

**Тело (`RegisterDto`):**

| Поле       | Тип    | Обязательное | Правила                          |
| ---------- | ------ | ------------ | -------------------------------- |
| `email`    | string | да           | валидный email                   |
| `password` | string | да           | 8–72 символа (72 — лимит bcrypt) |
| `name`     | string | нет          | до 100 символов                  |

**Ответ `201` (`AuthResponse`):**

```json
{
	"accessToken": "<jwt>",
	"user": {
		"id": "bf7e…",
		"email": "user@example.com",
		"name": "Александр",
		"createdAt": "2026-10-17T14:44:11.461Z",
		"updatedAt": "2026-10-17T14:44:11.461Z"
	}
}
```

**Ошибки:** `400` (невалидное тело), `409` (email уже существует).

### `POST /auth/login` — публичный

Вход по email и паролю.

**Тело (`LoginDto`):** `email` (валидный), `password` (непустая строка; минимальная длина для входа не проверяется).

**Ответ `200` (`AuthResponse`):** как у `register`.

**Ошибки:** `400`, `401` (неверный email или пароль — одинаковое сообщение против перебора).

### `GET /auth/me` — 🔒

Профиль текущего пользователя **из JWT-payload** (не полный `User`).

**Ответ `200` (`MeResponseDto`):**

```json
{ "id": "bf7e…", "email": "user@example.com", "name": "Александр" }
```

Обратите внимание: здесь нет `createdAt`/`updatedAt` — это payload токена, а не профиль из БД.

**Ошибки:** `401`.

## Categories — `/categories` — 🔒

CRUD категорий текущего пользователя. Все роуты защищены.

### `GET /categories`

Список категорий, отсортированный по `name` asc.

**Ответ `200`:** массив `Category[]`:

```json
[
	{
		"id": "99308771-8bda-4a0a-8a1b-ce3e9c747958",
		"name": "Продукты",
		"icon": "🛒",
		"color": "#FF5722",
		"createdAt": "2026-10-17T14:44:11.461Z",
		"updatedAt": "2026-10-17T14:44:11.461Z"
	}
]
```

### `POST /categories`

**Тело (`CreateCategoryDto`):**

| Поле    | Тип    | Обязательное | Правила                 |
| ------- | ------ | ------------ | ----------------------- |
| `name`  | string | да           | до 100 символов         |
| `icon`  | string | нет          | эмодзи, до 16 символов  |
| `color` | string | нет          | HEX-цвет (`IsHexColor`) |

**Ответ `201`:** созданная категория. **Ошибки:** `400`, `401`.

### `GET /categories/:id`

Категория по UUID (`ParseUUIDPipe`).

**Ответ `200`:** `Category`. **Ошибки:** `400` (id не UUID), `401`, `404`.

### `PATCH /categories/:id`

Частичное обновление. Тело `UpdateCategoryDto` = все поля `CreateCategoryDto` опциональны (PATCH-семантика — обновляются только переданные).

**Ответ `200`:** обновлённая категория. **Ошибки:** `400`, `401`, `404`.

### `DELETE /categories/:id`

**Ответ `200`:** удалённая категория. **Ошибки:** `400`, `401`, `404`.

## Transactions — `/transactions` — 🔒

Основной модуль учёта доходов/расходов. **Нет поля `currency`** — единая валюта `RUB`.

### `GET /transactions`

Постраничный список с фильтрами и пагинацией (offset). Сортировка по `date` desc, категория вложена.

**Query-параметры (все опциональны):**

| Параметр     | Тип                   | Правила                             | По умолч. |
| ------------ | --------------------- | ----------------------------------- | --------- |
| `dateFrom`   | string (ISO date)     | нижняя граница даты (включительно)  | —         |
| `dateTo`     | string (ISO date)     | верхняя граница даты (включительно) | —         |
| `type`       | `INCOME` \| `EXPENSE` | фильтр по типу                      | —         |
| `categoryId` | UUID                  | фильтр по категории                 | —         |
| `page`       | int                   | ≥ 1                                 | `1`       |
| `limit`      | int                   | 1–100                               | `10`      |

**Ответ `200` (`Paginated<Transaction>`):**

```json
{
	"items": [
		{
			"id": "1845d52e-0918-4949-ac9e-67353836ab18",
			"amount": 1200,
			"type": "EXPENSE",
			"description": "Покупка продуктов",
			"date": "2026-10-12T00:00:00.000Z",
			"categoryId": "99308771-8bda-4a0a-8a1b-ce3e9c747958",
			"category": {
				"id": "…",
				"name": "Продукты",
				"icon": "🛒",
				"color": "#22c55e",
				"createdAt": "…",
				"updatedAt": "…"
			},
			"createdAt": "2026-10-17T14:44:11.693Z",
			"updatedAt": "2026-10-17T14:44:11.693Z"
		}
	],
	"total": 12,
	"page": 1,
	"limit": 10
}
```

**Ошибки:** `400`, `401`.

### `POST /transactions`

**Тело (`CreateTransactionDto`):**

| Поле          | Тип                   | Обязательное | Правила                                                 |
| ------------- | --------------------- | ------------ | ------------------------------------------------------- |
| `amount`      | number                | да           | строго > 0 (`@Min(0.01)`)                               |
| `type`        | `INCOME` \| `EXPENSE` | да           | enum                                                    |
| `description` | string                | нет          | до 500 символов                                         |
| `date`        | string (ISO date)     | да           | `@IsDateString()`                                       |
| `categoryId`  | UUID                  | да           | `@IsUUID()`; категория должна принадлежать пользователю |

**Ответ `201`:** созданная транзакция (без вложенной категории). **Ошибки:** `400`, `401`, `404` (категория не найдена/чужая).

### `GET /transactions/summary` — ⚠️ статический маршрут

> Обрабатывается **до** `GET /transactions/:id` — порядок объявления маршрутов важен.

Сводка доходов/расходов за месяц.

**Query-параметры (оба обязательны):**

| Параметр | Тип | Правила |
| -------- | --- | ------- |
| `month`  | int | 1–12    |
| `year`   | int | ≥ 2000  |

**Ответ `200` (`TransactionsSummary`):**

```json
{ "month": 10, "year": 2026, "totalIncome": 3000, "totalExpense": 4800, "balance": -1800 }
```

Границы месяца — `[первый день, первый день следующего)` (UTC). `balance = totalIncome - totalExpense`. **Ошибки:** `400`, `401`.

### `GET /transactions/:id`

Транзакция по UUID со вложенной категорией.

**Ответ `200`:** `Transaction` (с `category`). **Ошибки:** `400`, `401`, `404`.

### `PATCH /transactions/:id`

Частичное обновление. Тело `UpdateTransactionDto` = все поля `CreateTransactionDto` опциональны.

**Ответ `200`:** обновлённая транзакция. **Ошибки:** `400`, `401`, `404`.

### `DELETE /transactions/:id`

**Ответ `200`:** удалённая транзакция. **Ошибки:** `400`, `401`, `404`.

## Авторизация для вызовов

```bash
# 1. Получить токен
curl -X POST http://localhost:3001/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"strongPassword123"}'

# 2. Использовать токен
curl http://localhost:3001/transactions \
  -H 'Authorization: Bearer <accessToken>'
```

Токен подписывается `JWT_SECRET` (`.env`), срок жизни — `JWT_EXPIRES_IN` (по умолч. `7d`).
