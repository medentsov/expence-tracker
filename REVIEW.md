# REVIEW.md — Правила Code Review

Правила ревью изменений в монорепозитории трекера расходов. Применяются ко всем PR и коммитам в `main`. Общие принципы разработки и архитектура — в корневом `CLAUDE.md`; специфика воркспейсов — в `apps/api/CLAUDE.md` и `apps/web/CLAUDE.md`.

## Когда проводить ревью

- **Перед PR** — каждый PR проходит ревью (self-review или коллегой) перед мёрджем в `main`.
- **По запросу** — `/code-review` с уровнем `medium` (по умолчанию) или `high` (для существенных изменений).
- **После исправлений** — повторное ревью только изменённых мест.

## Уровни ревью (`/code-review <level>`)

- `low` — быстрая проверка, несколько высокоуверенных замечаний.
- `medium` — баланс, используется по умолчанию.
- `high` — глубокий разбор, включая пограничные случаи и архитектурные риски.
- `max` — максимально подробный, для критичных изменений.

## Что проверять

### 1. Безопасность

- **Изоляция по `userId`** — все запросы к данным пользователя фильтруются по `userId` из `@CurrentUser()`. Чужая запись → 404 (не отличима от несуществующей). Проверить ownership-хелперы (`*-ownership.ts`).
- **Авторизация** — глобальный `JwtAuthGuard` защищает все роуты; публичные эндпоинты помечены `@Public()`. Токен не утекает в логи/ответы.
- **Пароли** — `bcryptjs` (cost 10), `passwordHash` не попадает в ответы (очищается в `UsersService.toPublicUser`).
- **JWT** — секрет/срок жизни из env (`JWT_SECRET`/`JWT_EXPIRES_IN`), не зашиты в код. `JwtModule.registerAsync` с fail-fast.
- **Валидация** — `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`); DTO с class-validator на всех входных данных.
- **XSS** — React экранирует; опасно `dangerouslySetInnerHTML`, `eval`, инъекции в SQL (используем Prisma — параметризованные запросы).
- **CORS** — `main.ts` разрешает только `http://localhost:3000`; при развёртывании добавить домен.
- **Секреты** — `.env` в git не попадает; `apps/api/.env` локальный. Проверить отсутствие хардкоженых токенов/ключей.

### 2. Качество кода

- **TypeScript strict** — включён (`tsconfig.base.json`); без `any` без веской причины, без `@ts-ignore`.
- **Дед_code** — функции должны «зарабатывать своё место»; без избыточной абстракции, мёртвого кода, копипасты.
- **Именование** — понятно и консистентно; типы/интерфейсы — по конвенции.
- **Обработка ошибок** — на trust-границах (API-вызовы, парсинг); `ApiError` пробрасывается с человекочитаемым сообщением; сетевые сбои (`status: 0`) не сбрасывают сессию без причины.
- **Trailing newline** — файлы заканчиваются переводом строки (в проекте принято).
- **Комментарии** — там, где неочевидно; комментарии зеркалят реальные правила (DTO → zod).

### 3. Паттерны и архитектура

#### Feature-Sliced Design (`apps/web`)
- **Импорты только вниз** — `app` → `views` → `features` → `entities` → `shared`. Кросс-импорты внутри слоя **запрещены**.
- **Публичный API слайса** — через `index.ts`; наружу экспортируется минимальное (обычно UI-компонент для features, API-функции для entities).
- **Токен передаётся аргументом** — `entities` не импортирует `session` внутри себя (нарушает FSD). Хук вызывает `getToken()` и передаёт в `apiFetch`.
- **Структура feature-слайса** — `index.ts` + `api/` (опц.) + `model/` (`schema.ts`, `use-*.ts`) + `ui/`.
- **Структура entity-слайса** — `index.ts` + `api/` + `model/` (для session).
- **Zod-схемы зеркалят DTO бэкенда** — правила валидации синхронны с `apps/api/src/modules/*/dto`.

#### CQRS (`apps/api`)
- **Модули общаются только через шины** — без прямых импортов друг друга. Контроллер → `CommandBus`/`QueryBus` → хендлер.
- **Хендлер живёт в модуле-владельце данных** — `@CommandHandler`/`@QueryHandler`/`@EventsHandler`, находится глобально через `ExplorerService`.
- **Структура модуля** — `*.module.ts`, `*.controller.ts`, `*-ownership.ts`, `commands/` (+`handlers/`), `queries/` (+`handlers/`), `dto/`, опц. `events/`.
- **`users`** — без контроллера, только хендлеры через шину; наружу ничего не экспортирует.
- **Новый код вести через `transactions`** — `expenses` — legacy.

#### Shared-типы (`packages/shared`)
- **Синхронизация с DTO** — при изменении DTO/ответа API обновить соответствующий интерфейс в `packages/shared/src/types/`.
- **Импорт как `@tracker/shared`** — `import type` во фронтенде.

### 4. Проверки перед мёрджем

Все три должны быть зелёными:
```bash
npm run typecheck   # 3/3 воркспейса
npm run lint        # 3/3 воркспейса
npm run build       # успешно, роуты собраны
```

### 5. Git и коммиты

- **Conventional Commits** — `<type>(<scope>): <описание>` на русском. Типы: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`. Scope: `api`, `web`, `shared`.
- **Атрибуция** — каждое сообщение завершается `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
- **GitHub Flow** — прямые коммиты в `main` запрещены; только через PR (`gh pr create`). После мёржа ветка удаляется.
- **PR-описание** завершается строкой `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

## Вероятные находки (из прошлого ревью)

- **UTC-дата в формах** — использовать `shared/lib/date.ts:todayInputDate()`, не `toISOString().slice()`.
- **Перемонтирование через `key`** — вместо `key={version}` использовать `refetch` из хуков; избегать скелетонов/мерцания.
- **Несброшенная форма/ошибка** — сбрасывать в `onOpenChange(false)`.
- **`page` вне диапазона** — подрезать при уменьшении `total`.
- **Лишние запросы** — ленивая загрузка (по `enabled`/`open`), не при монтировании.

## Чего НЕ считать дефектом (типовые ложные срабатывания)

- `import { cn } from "cn"` и `import { Dialog } from "radix-ui"` в shadcn-компонентах — штатные импорты shadcn CLI 4.x (проверено, сборка проходит).
- `Date → ISO` в ответах API — в хендлерах `transactions` сериализация идёт явно через `.toISOString()`.
